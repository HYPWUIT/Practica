# Sage & Oak

Online furniture shop: a React client plus an Express API, with auth, on local
PostgreSQL. It follows the global stack in `~/.claude/CLAUDE.md`. This file
only covers what is specific to this project, including where it differs from
that stack.

## Layout

A Bun workspace. **It is not `apps/` + `packages/`**: the client already
existed at the root when the backend was added, so the packages sit side by
side.

```
client/   React 19 + Vite 8 + Tailwind 4 + React Router 8 + TanStack Query
server/   Express 5 + Prisma 7 (pg driver adapter) + Better Auth
shared/   @sage-oak/shared — Zod schemas, inferred types, catalogue seed data
e2e/      Playwright tests
```

- `@sage-oak/shared` exports `.` (schemas and types) and `./data` (the 24
  products and 5 jobs, used as seed data and by tests).
- Read the docs before changing behaviour: `project-scope.md` (scope),
  `implementation-plan.md` (every step, its commit and how it was checked),
  `RETRO.md` (what went wrong with AI before; take it seriously).
- `README.md` is in **Romanian**. Keep it that way when you edit it.

## Commands

From the root:

| Command | What it does |
|---|---|
| `bun run dev:server` / `bun run dev:client` | API on :3000 / site on :5173 (Vite proxies `/api` → :3000) |
| `bun run lint` / `bun run typecheck` | All workspaces |
| `bun run test` | `bun test` in `shared/` (unit) and `server/` (integration) |
| `bun run test:e2e` | Playwright; starts its own API :3100 + client :5174 |

From `server/`: `bun run db:migrate`, `db:seed`, `db:generate`, `db:studio`.

## Rules and gotchas

**Prisma**

- Always run the Prisma CLI through the `db:*` scripts, never bare
  `bunx prisma`. Bun's automatic `.env` loading does not reach the `prisma`
  binary, so the scripts pass `--env-file=.env`.
- `prisma.config.ts` reads `process.env.DATABASE_URL ?? ''`, not `env()`, so
  that `postinstall`'s `prisma generate` works on a fresh clone with no `.env`.
  Keep it that way.
- `prisma migrate dev` does not regenerate the client in Prisma 7. Run
  `db:generate` after schema changes.
- The Better Auth models in `schema.prisma` were generated by the Better Auth
  CLI for the installed version (`bunx auth@<version> generate --adapter
  prisma`). Regenerate them after upgrading `better-auth`. Newer docs show
  columns that 1.7.x does not have.
- The catalogue enums in `schema.prisma` must match the Zod enums in
  `shared/src/product.ts`. `toProduct()` in `server/src/lib/catalog.ts` fails
  to typecheck if they drift apart.

**Databases**

- Development: `sage_oak`. Tests use `sage_oak_test` (the `DATABASE_URL`
  name + `_test`), which `server/test/setup.ts` and `e2e/playwright.config.ts`
  migrate and seed themselves. Both refuse any database whose name does not
  end in `_test`.
- **Never** write test data to `sage_oak`. The user has a real account there.
  If you must use the dev database for a manual check, delete what you
  created.
- Credentials live in `server/.env` (git-ignored). Never commit it or print
  its values.

**Auth**

- Better Auth is mounted at `/api/auth/*splat` **before** `express.json()`.
- `advanced.disableOriginCheck: false` is deliberate: Better Auth turns the
  origin check off whenever `NODE_ENV=test`. Do not remove it.
- Every field that sets a name or a password goes through the before-hook in
  `server/src/lib/auth.ts` (`bodyChecks`), using the shared schemas. When you
  add an auth endpoint that accepts such a field, add it there too.
- Client: `AuthProvider` wraps `better-auth/react`. Pages use `useAuth()`,
  never the auth client directly. `?next=` redirects go through `nextPath()`
  in `client/src/lib/redirect.ts`, which only allows same-site paths.

**Data shapes**

- Define a shape once as a Zod schema in `shared/`, infer the type, and use it
  for forms (`zodResolver`), server validation and tests.
- The API's error body is always `{ error, issues? }`. Zod errors → 400 with
  `issues[].path`.
- Prices are integer cents; dimensions are centimetres.
- The catalogue endpoint must return the same results, in the same order, as
  the client's `filterProducts` (`client/src/lib/filter.ts`).
  `server/test/catalog.test.ts` uses that function as the reference.

**Client**

- Every catalogue read goes through `client/src/api/catalog.ts`. Pages never
  call `fetch` themselves.
- Routes are lazy-loaded via the `page()` adapter in `router.tsx`: React
  Router wants a `Component` export, while pages use `export default`.
- Still client-only (see "Later" in `implementation-plan.md`): the cart,
  checkout, the contact/career/newsletter forms, and the filter-sidebar
  counts.

## Code style

- There is **no Prettier config yet**. Match the existing code: no
  semicolons, single quotes, 2-space indent, trailing commas, lines of about
  80 characters.
- `strict` is on in `server/`, `shared/` and `e2e/`. `client/tsconfig.app.json`
  predates this rule and does not set it. Don't enable it as a side effect of
  an unrelated change.
- Comments explain *why*, not *what*, and the code uses plenty of them. Keep
  that density.
- Use union types or Zod enums, not TS `enum` (`erasableSyntaxOnly`).

## Working rules

- **Small steps:** one logical change per commit. Propose a numbered plan for
  bigger work, verify each step before committing it, and pause for the user
  between steps.
- **Verify in a real browser.** A green build or HTTP 200 proves nothing in an
  SPA (see `RETRO.md`). Render the page, or run Playwright.
- **Make every new test fail once** by breaking the code in a way that still
  compiles, then restore it.
- **When a test fails, decide whether the test or the app is wrong before
  reporting an app bug.** Ambiguous locators (`getByLabel('Password')` also
  matches "Confirm password"; use `exact: true`) have been the usual culprit.
- **E2E runs against the production build** (`vite preview`), not
  `vite dev`. The dev server stalls under parallel cold loads.
- **Processes:** the user often has their own `vite` / API running on
  3000/5173. Before stopping anything on those ports, check the PID and start
  time; only stop processes you started.
- **Dependencies:** after any change to them, install from the root. A stale
  `client/node_modules` from before the workspace once caused two copies of
  React ("Invalid hook call").
- **Git:** work on the `test` branch. `origin/test` still points at an old
  branch, so pushing needs a decision from the user (force-push or delete the
  remote branch). Don't push without asking.
